Pre-Trade Pipeline / Consensus Gates

/ SIGNAL → WIRE

Six sequential gates between a strategy emitting a signal and an order hitting the exchange. Each gate can reject, trim, or pass through. Target end-to-end budget: under 50 ms.

sequenceDiagram autonumber participant S as Strategy participant V as SignalValidator participant A as PortfolioAggregator participant Z as PositionSizer participant R as RiskOverlay participant I as IdempotencyOMS participant E as ExecutionEngine participant X as Exchange S->>V: SignalEvent (side, strength, ttl, meta) V->>V: schema, ttl, strategy enabled, rate limit alt rejected V-->>S: risk.rejected.signal_invalid else passed V->>A: validated signal A->>A: combine across strategies, allocate capital A->>Z: target position Z->>Z: delta, vol-target, tick rounding Z->>R: candidate order R->>R: A - sanity (qty, collar, ADV, instrument live) R->>R: B - margin (pre-trade sim, exposure caps) R->>R: C - envelope (loss limit, drawdown, killswitch) R->>R: D - cross-strategy (rate-limit, no unwind conflict) alt any layer rejects R-->>S: risk.rejected.reason else borderline soft-cap R-->>S: risk.trimmed R->>I: trimmed orders.intent else all pass R->>I: orders.intent end I->>I: clientOrderId = hash(strategy_id, intent, time_bucket) I->>E: deduplicated intent E->>E: smart routing (TWAP, passive, iceberg) E->>X: submit X-->>E: ack, partial fill, fill, reject E-->>S: orders.id.status, fills.id E-->>R: post-trade slippage reconcile end

/ READ-SIDE PROJECTION

ProjectionWriter is fire-and-forget — Redis can die without affecting trading. Dashboard API runs in a separate process, reads from Redis + TimescaleDB only, never touches the bus. Controls flow back through a small local-socket interface.
